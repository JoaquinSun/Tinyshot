# TinyShot

一个原生 macOS 菜单栏截图暂存工具。保留 ⇧⌘4 的截图习惯，让截图停留在悬浮窗里，直到你复制或成功拖放到其他软件。

支持多张截图、复制与拖放、重启恢复，以及可切换的 Liquid Glass 外观。图片只在本机处理，无第三方依赖。采用 [MIT 许可证](LICENSE)。

## 开始使用

从 [Releases](https://github.com/JoaquinSun/Tinyshot/releases/latest) 下载通用版 ZIP，解压后把 `TinyShot.app` 拖到「应用程序」。支持 Apple Silicon 和 Intel Mac。应用尚未经过 Apple 公证；若被系统拦截，确认来源后按照 [Apple 官方说明](https://support.apple.com/en-us/102445)，在「系统设置 → 隐私与安全性」选择「仍要打开」。

也可从源码构建（详见下方工具链要求）：

```sh
zsh scripts/build.sh
open dist/TinyShot.app
```

1. 首次运行会显示引导窗口，之后驻留菜单栏。
2. 按 **⇧⌘5 → 选项**，取消勾选 **显示浮动缩略图**。这一步由你手动设置，TinyShot 不会修改系统偏好。
3. 确认系统截图的「存储到」与 TinyShot 监听的文件夹一致。默认读取当前系统配置；没有自定义位置时使用桌面。如果系统要求访问文件夹，请按需允许，或在 TinyShot 中选择截图文件夹。
4. 继续按 **⇧⌘4**。截图保存成文件后，TinyShot 会显示可持续保留的卡片。
5. 把卡片里的图片拖入 AI 软件，或点「复制」后在目标软件中按 **⌘V**。

点击菜单栏的取景框图标显示/隐藏暂存窗；右键打开菜单、设置或退出应用。关闭主窗口后，应用继续在菜单栏运行。打开 `.app` 也能重新打开主窗口。

## 功能与文件处理

- 偏好设置提供「液态玻璃」开关，默认开启、实时生效并记住选择。macOS 26+ 使用原生 Liquid Glass，旧版 macOS 使用磨砂材质；关闭后使用浅色外观。
- 液态玻璃模式跟随系统浅色/深色外观，并尊重「降低透明度」。效果应用于托盘、主窗口和按钮，不改变截图像素。
- 默认一直悬浮；复制成功或目标软件接受拖放后自动收起。拖放被取消或拒绝时保留。
- 可以关闭「使用后自动收起」，或改为 1 / 5 / 15 分钟后收起。
- 默认开启「拖出后删除原图」：目标软件接受拖放后，原文件直接删除，不进废纸篓。仅复制、取消拖放或到时收起都不会触发删除。此开关独立于「使用后自动收起」。
- 拖放会使用独立的本地临时副本，避免删除原文件影响目标软件继续读取。没有卡片或进行中的拖放引用的副本，在创建满 24 小时后由运行中的应用清理；应用退出期间则在下次启动时清理。
- 支持连续多张截图，暂存窗内滚动查看；应用不会自行上传图片。关闭「拖出后删除原图」可保留拖放后的原文件。
- 卡片数量变化时保持悬浮窗底部位置，从上方展开或收缩；图片区域单独处理拖放，避免被识别为移动悬浮窗。
- 点卡片右上角的 × 会直接删除对应截图文件并移除卡片，不进废纸篓，也不进入「最近收起」；不受「拖出后删除原图」开关影响。删除失败时保留卡片并提示。顶部「− 收起」是独立按钮（点击区域至少 64×32），只隐藏窗口，可从菜单栏再次打开。未使用截图会在下次启动时恢复。
- 「最近收起」最多保留 24 条仍有原图的文件引用，可放回暂存；已通过拖放删除原图的截图不会出现在这里，也无法从废纸篓恢复。
- 「试试示例」会创建明确标注的示例图片，方便测试复制和拖放，遵循相同的删除设置。
- 图片与暂存状态仅在本机处理。记录保存在 `~/Library/Application Support/TinyShot/`。

## 边界

- **没有接管系统的浮动缩略图**。如果保留系统缩略图，需要等 macOS 完成保存，再出现 TinyShot 卡片。关闭系统缩略图可省去这段等待；文件保存与检测仍存在短暂延迟。
- 监听的是选定文件夹中的新文件。启动时已有截图不会批量导入，历史未用卡片从暂存记录恢复。
- 仅保存到剪贴板的截图（如 ⇧⌘⌃4）不产生文件，因此不会被捕获。系统截图「存储到」应设为文件夹，而不是剪贴板或其他应用。
- 截图通过系统元数据和常见语言的系统文件名前缀识别，也支持系统自定义截图名称。某些未覆盖语言或第三方截图工具的输出可能无法识别。
- 系统截图位置发生变化后，需要在 TinyShot 中选择新的文件夹。
- 拖放被接受只代表目标收到了文件，不代表 AI 已完成上传；复制成功也不代表已经粘贴。目标软件必须支持图片粘贴或文件拖放。临时副本保留 24 小时供继续读取，不提供云端上传完成检测。
- 原图在拖放期间被修改或替换时不会删除；删除失败时会保留卡片并提示。关闭自动收起时，已删除原图的卡片使用临时副本继续显示，副本在卡片被收起前不清理。这种卡片点击 × 后只移除卡片，上传副本仍按 24 小时的规则清理，避免中断读取。
- 当前构建采用临时本地签名，尚无公证、自动更新、开机自启或编辑标注功能；普通构建匹配构建机器架构，Release 打包脚本生成 Apple Silicon / Intel 通用版。

## 构建与验证

运行需要 macOS 13+；原生液态玻璃需要 macOS 26+。构建需要 Swift 6.2+ 和 macOS 26 SDK（例如 Xcode 26.0.1，或对应的 Command Line Tools），测试需要 macOS 14+。完整 Xcode 需先通过 Apple 的正常流程完成安装与许可设置。项目不使用第三方依赖。

```sh
zsh scripts/build.sh
zsh scripts/test.sh
python3 scripts/check-public.py
```

构建结果：`dist/TinyShot.app`。也可以在 Xcode 中打开 `Package.swift` 阅读和修改源码。

测试使用 Swift Testing（运行测试需要 macOS 14+ 的测试框架），覆盖截图识别与监听、持久化、复制完成后保留原图、成功拖放后直接删除、取消拖放、删除开关、拖放期间原图改变、删除失败、重复回调、临时副本读取与清理，以及保留卡片的保护。删除测试仅使用测试目录中的生成图片，不操作桌面上的真实截图。脚本为当前 Command Line Tools 的测试框架配置了显式搜索路径，不修改全局开发工具设置。

手动验收建议：

1. 点「试试示例」，确认其他软件成为前台时截图仍悬浮。
2. 把示例图片拖到不接受文件的区域，确认卡片与原文件保留；再拖到支持图片的输入框，确认接受后收起，原文件直接删除，目标仍能读取图片。
3. 复制图片后，在支持图片的输入框粘贴；在「最近收起」中恢复卡片。
4. 连续截图，退出再启动，确认未用卡片恢复。
5. 测试多显示器、全屏空间、实际截图格式，以及所用 AI 客户端的拖放支持。

截图选项的官方说明：[Apple：在 Mac 上截屏或录屏](https://support.apple.com/en-au/guide/mac-help/mh26782/27/mac/27)。
